Buzz bridge: dark-wake stale-timestamp refusal, end-to-end drill
================================================================

Reported incident: the home-local Buzz bridge woke the owner with
"relay refused the bridge key (auth error); check channel membership" while the
Mac lid was closed. The Buzz CLI's captured stderr showed the real cause:

  rc=3 {"error":"auth_error","message":"auth error: relay requires authentication
  (NIP-98: NIP-98 HTTP Auth verification failed: event timestamp outside +/-60s
  window (delta: 106s)) ...","retryable":false}

The drill below runs the real bin/fm-buzz.sh and bin/fm-buzz-poll.sh against a
fake pinned Buzz CLI that returns exactly that payload, and prints what the
owner would see: the wake lines the poll emits (the watcher turns these into
notifications), the delivered request, and `fm-buzz.sh status`.

Driver: buzz-skew-drill.sh (in this evidence directory)
Scenario "once"       = one refused signature, then the relay accepts (the incident)
Scenario "persistent" = the host clock stays outside the window
Scenario "membership" = a genuine key/membership refusal
